# 开发路线图（阶段 0 → 发布）

- 基线：`6664c91`，游戏主体已实现（历史阶段 1–7）。
- 因此本路线图**不是从零开发**，而是“验证 → 修复 → 产品化 → 发布”。
- 阶段 0 的结论是**条件式 GO**；阶段 1 的第一件事不是加功能，而是关闭真机/发布门禁。

## 3. 阶段 1：真机与发布门禁（P0）

**目标：证明“在真实 Android 17 设备上可玩、可发布”，而不是继续加功能。**

### P1.1 Android 17 真机验证（3–5 人日）

| 项 | 内容 |
|---|---|
| 设备 | Pixel 8/9 或同级 Android 17（API 37） |
| 步骤 | 安装 debug APK → 冷启动 → 练习模式 → 开球 → 打完一局 → 暂停/恢复 → 后台 10 min → 回来 |
| 采集 | `adb shell dumpsys gfxinfo <pkg> framestats`；`adb shell dumpsys meminfo`；电池/温度；logcat |
| 指标 | 冷启动 ≤2 s（Pixel）；对局 p95 帧 ≤16.6 ms；无 ANR/黑屏；物理无穿透 |
| 失败处理 | 按 RENDERING_DESIGN 9.3 降级：低模球、去 Fresnel、256 纹理、关 mipmap；仍不达标则评估 30 fps 锁定 |
| 产出 | `docs/validation/DEVICE_PIXEL_ANDROID17.md` + gfxinfo/meminfo 原始日志 |

### P1.2 折叠屏/大屏/分屏（2–3 人日）

| 项 | 内容 |
|---|---|
| 设备 | Pixel Fold / Pixel Tablet / 任意折叠屏 |
| 场景 | 展开→合上→再展开；tabletop；分屏 50/50；自由窗口拖动 |
| 检查 | 是否重建 Activity；GL 是否黑屏；相机是否跳变；触控落点是否偏移；HUD 是否被铰链/系统栏遮挡 |
| 指标 | 无重建；触控误差 < 1 球半径；台面完整可见；按钮可点 |
| 产出 | 折叠屏验证记录；如需铰链避让，单独立项（不在本阶段默认做） |

### P1.3 触觉三机型（1–2 人日）

| 项 | 内容 |
|---|---|
| 设备 | Pixel、Samsung、小米/OPPO 各一 |
| 场景 | 轻碰、重碰、库边、落袋、犯规、胜负；连续开球 |
| 检查 | 强度可区分；无“麻手”；无马达设备不崩；系统关闭触觉时静默 |
| 指标 | 主观 4/5 分；事件不粘连 |
| 产出 | 触觉体感记录；必要时调振幅/冷却 |

### P1.4 签名与发布产物（1–2 人日）

| 项 | 内容 |
|---|---|
| 动作 | 生成 upload keystore；配置 `signingConfigs`；产出 AAB；启用 Play App Signing |
| 安全 | keystore 不入库；CI secret/本地加密备份；记录指纹 |
| 验收 | `bundletool build-apks` 可安装；`apksigner verify` 通过；debug/release 可共存（applicationId 后缀已处理） |
| 产出 | 签名 AAB + 签名说明（不包含密钥本身） |

### P1.5 兼容修复（2–3 人日）

| 编号 | 修复 | 验收 |
|---|---|---|
| F1 | API 28–29 横屏读取 `displayCutout.safeInset*` | 刘海机横屏按钮不被遮挡 |
| F2 | manifest 加 `android:enableOnBackInvokedCallback="true"` | Android 13–17 返回手势一致 |
| F3 | `onTrimMemory` 释放/重建非必要纹理 | 后台 30 min 回来不黑屏 |
| F4 | 修正 `Prefs` 触觉注释（0.2–1.0） | 文档一致 |
| F5 | 统一开球静止时间表述 | 文档一致 |

### P1.6 CI/回归（2–3 人日）

| 项 | 内容 |
|---|---|
| API37 | 增加 API37 emulator job（镜像可用时）；不可用则用 Firebase Test Lab 真机 |
| GL 断言 | 仪器测试加帧计数/`glGetError` 检查；至少渲染 60 帧不报错 |
| 折叠 | 仪器测试用 `DeviceConfigurationOverride` 或 `UiAutomation` 改尺寸（可用时） |
| 性能 | 记录 benchmark 基线（不作为硬门禁，防噪声） |
| 产出 | 绿的 CI + 可下载测试报告 |

### Gate A（阶段 1 出口）

- [ ] 真机 p95 ≤16.6 ms（或产品批准的降级目标）
- [ ] 折叠屏展开/合上/分屏无黑屏/无重建/触控准确
- [ ] 触觉三机型通过
- [ ] 签名 AAB 可安装/可升级
- [ ] API37 CI 或真机回归绿
- [ ] F1–F4 关闭

> 未过 Gate A，不进入阶段 2 的功能开发；只允许修复门禁问题。

## 4. 阶段 2：产品化（P1）

### P2.1 英文本地化（3–5 人日）

- 现状：Canvas 文案硬编码中文；`resourceConfigurations zh,en` 但没有完整英文。
- 动作：
  1. 抽出 `strings.xml`（含 HUD/菜单/帮助/结算）；
  2. Canvas 通过 `context.getString()` 取文案；
  3. 英文翻译 + 长度回归（英文通常更长，按钮要自适应）；
  4. 日期/数字格式不依赖 locale。
- 验收：系统语言 en-US 下主流程可读；无截断；中文不受影响。

### P2.2 无障碍（5–8 人日）

- 现状：Canvas View 无虚拟节点，TalkBack 基本不可用。
- 最小方案：
  1. 菜单/暂停/结算的关键按钮建 `AccessibilityNodeProvider` 虚拟节点；
  2. 设置 `contentDescription`、`isFocusable`、焦点顺序；
  3. 力度/杆法提供可读数值（不只颜色/图形）；
  4. 触控目标 ≥48 dp；对比度 ≥4.5:1。
- 验收：TalkBack 完成“主菜单→练习→瞄准→击球→暂停→返回”。
- 若工作量超预期，至少保证“可开始对局/可暂停/可退出”，并在商店标注限制。

### P2.3 音频（2–3 人日）

- 替换 9 个合成 WAV 为可商用采样（或继续程序化但提升质感）；
- 统一响度（建议 -16 LUFS 左右）、去爆音、淡出；
- 保留 `SoundBank` 接口与冷却；
- 验收：无破音；连续碰撞不刺耳；包体增量可控。

### P2.4 引导/帮助/设置（3–5 人日）

- 首次进入 3 步引导：瞄准、力度、杆法；
- 帮助页说明规则/犯规/自由球；
- 设置：声音、触觉、强度、画质、语言；
- 验收：新用户 1 分钟内能完成第一杆。

### P2.5 存档/生命周期健壮性（2–3 人日）

- 关键存档改 `commit()`（后台线程）或加“保存中”保护；
- 进程死亡恢复提示；
- 存档损坏回退不崩溃（已有 `runCatching`，补测试）；
- 验收：杀进程/旋转/分屏/后台恢复均不丢稳定局面。

### P2.6 AI 与手感（3–5 人日）

- AI 目前是几何选球 + 固定误差；增加难度档（误差/搜索深度）；
- 调物理参数（滚动摩擦、库边恢复、袋口）做 3 档手感；
- 验收：新手能进球；高手不被“弱智 AI”破坏体验；无必输/必赢bug。

### Gate B（阶段 2 出口）

- [ ] 英文可用
- [ ] TalkBack 主流程可用
- [ ] 音频替换完成
- [ ] 引导/帮助完成
- [ ] 存档/生命周期回归通过
- [ ] AI 三档可玩

## 7. 测试策略

### 7.1 分层

| 层 | 工具 | 频率 | 门禁 |
|---|---|---|---|
| 单元（物理/规则） | JUnit4，34 个现有 + 新增 | 每次提交 | 全绿 |
| 不变量模糊 | JUnit + 随机种子 | 每晚 | 无 NaN/穿透/四元数异常 |
| 仪器（启动/绘制） | AndroidX Test，API35/37 | 每次 PR | 全绿 |
| GL 冒烟 | 帧计数 + `glGetError` | 每次 PR | 60 帧无错 |
| 真机性能 | gfxinfo/profiler | 每里程碑 | p95 ≤16.6 ms |
| 折叠/触觉 | 人工清单 | 每里程碑 | 清单全过 |
| 长稳 | 30–60 min 自动对局 | RC | 无 OOM/ANR |

### 7.2 新增测试建议

1. `PhysicsWorldInvariantTest`：10k 随机击球，断言有限/在界/无重叠。
2. `SnapshotHashTest`：固定种子 100 组，3000 步状态哈希稳定。
3. `GlSmokeTest`：`GLSurfaceView` 渲染 60 帧，`glGetError==0`。
4. `SaveStoreCorruptionTest`：缺字段/错版本/空 balls/非法 enum 全部返回 null。
5. `WindowSizeTest`：用 `DeviceConfigurationOverride` 覆盖 600×900、900×1600、1600×2560。

## 10. 决策记录（ADR 摘要）

| 决策 | 选择 | 理由 | 何时复审 |
|---|---|---|---|
| 物理 | 自研 | 台球专用、纯 Kotlin、可单测、性能足够 | 若要做跳球/3D |
| 渲染 | GLES3 前向 | 覆盖广、代码小、50 draw call | 若帧率不达标且降级无效 |
| UI | Canvas | 无 XML/Compose 依赖、横竖屏可控 | 若无障碍成本过高 |
| 线程 | 独立模拟线程 | 固定步长/确定性 | 若 ANR/生命周期问题 |
| 存档 | SharedPreferences JSON | 单局、小数据、无 IO 复杂度 | 若要多局/回放 |
| 方向 | fullSensor | Android 17 大屏自适应；不依赖 opt-out | 若产品要求锁定手机 |
| 发布 | target 37 | 避免二次迁移 | 若商店要求变化 |
