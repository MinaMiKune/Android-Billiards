# 物理设计（阶段 0）

- 实现：`core/src/main/kotlin/com/minamikune/billiards/physics/PhysicsWorld.kt`（537 行）
- 参数：`Ball.kt` 中的 `TableSpec`
- 结论：**自研 2D 刚体 + 旋转模型可行**；最小原型已跑通并有量化数据，不需要 Box2D/Bullet。
- 边界：这是“台球专用”模型，不是通用刚体引擎；不支持跳球、扎杆弧线、球体形变。

---

## 1. 坐标、单位与状态

### 1.1 坐标系

```text
桌面平面：x 沿长边（-1.27 .. +1.27 m）
          y 沿短边（-0.635 .. +0.635 m）
垂直方向：z（重力 -z；物理内部只显式使用角速度 z 分量）
```

- 物理坐标永远是“桌面坐标”，与横竖屏无关；`TableSpace` 负责映射到渲染世界：
  - 横屏：`world = (x, 0, y)`
  - 竖屏：`world = (y, 0, -x)`（桌面绕世界 Y 轴旋转 +90°）
- 球心高度固定为 `r`，不做竖直平动；因此不需要 3D 刚体求解。

### 1.2 状态量

| 量 | 类型 | 说明 |
|---|---|---|
| `position` | `Vec2` | 球心在桌面平面的位置 |
| `velocity` | `Vec2` | 线速度 m/s |
| `angularVelocity` | `Vec3` | `(ωx, ωy, ωz)`；`ωx/ωy` 是滚动轴，`ωz` 是竖直自转 |
| `orientation` | `Quat` | 仅用于渲染球面标记；每步积分 |
| `active` / `asleep` / `pocketIndex` | `Boolean/Int` | 是否在台、是否睡眠、落袋编号 |

### 1.3 参数基线

| 参数 | 值 | 说明 |
|---|---:|---|
| 台面长 × 宽 | 2.54 × 1.27 m | 9 尺台 |
| 球半径 `r` | 0.028575 m | 直径 57.15 mm |
| 球质量 `m` | 0.17 kg | 所有球相同 |
| 转动惯量 `I` | `0.4 m r² = 5.5524e-5 kg·m²` | 实心球 |
| 重力 `g` | 9.81 m/s² | |
| 滑动摩擦 `μs` | 0.22 | 球-呢 |
| 滚动阻力 `μr` | 0.020 | 纯滚动减速度 `μr g` |
| 滑动自转衰减 `λs` | 3.8 s⁻¹ | `ωz` 指数衰减 |
| 滚动自转衰减 `λr` | 1.35 s⁻¹ | `ωz` 指数衰减 |
| 球-球恢复系数 `e_b` | 0.95 | |
| 库边恢复系数 `e_c` | 0.74 | |
| 球-球摩擦 `μ_b` | 0.06 | 切向冲量上限 |
| 球-库摩擦 `μ_c` | 0.18 | 切向冲量上限 |
| 袋角半径 / 恢复系数 | 0.012 m / 0.62 | 12 个静态圆角柱 |
| 角袋口半宽 | 0.105 m | |
| 中袋口半宽 | 0.072 m | |
| 中袋/角袋捕获半径 | 0.075 / 0.090 m | |
| 最大线速度 / 角速度 | 12 m/s / 900 rad/s | 数值安全上限 |
| 睡眠速度 / 角速度 / 时间 | 0.006 m/s / 0.35 rad/s / 0.32 s | |

> 用户实际可击出的最大速度是 **9.0 m/s**（`MatchEngine.strike()`：`0.8 + power × 8.2`，`power ∈ [0,1]`）。12 m/s 只作为物理安全上限和压力测试值。

## 2. 固定步长

```text
GameLoop.STEP = 1 / 480 s
PhysicsWorld.step(dt) 要求 0 < dt <= 1/60
```

`GameLoop` 用累加器把渲染帧时间切成 480 Hz 的整数步；每帧最多 140 步，超出时丢弃余量，避免后台恢复后的“死亡螺旋”。

### 2.1 为什么是 480 Hz

| 场景 | 每步位移 | 与几何尺寸比较 |
|---|---:|---|
| 单球 12 m/s | 25.0 mm | < 球半径 28.575 mm |
| 两球相向各 12 m/s | 50.0 mm | < 球直径 57.15 mm |
| 球撞库 12 m/s | 25.0 mm | < 球半径 28.575 mm |

因此正常玩法下不会穿透；袋口另有扫掠检测，不依赖离散重叠。代价是每帧 8 步（60 fps）的 CPU；实测远低于预算。

### 2.2 与 Android 生命周期的关系

- 物理核心是纯 Kotlin，不持有 Android 对象，不依赖 `Choreographer`/`Sensor`。
- `onPause` 停止模拟线程；恢复时累加器归零，不补算后台时间。
- 每次 `step` 都是纯函数式推进（输入：当前状态 + `Strike`；输出：新状态 + 事件），因此可以暂停/恢复/重放。
- 存档只保存状态，不保存“进行中的积分”；恢复后从稳定态继续。

## 3. 单球积分

### 3.1 接触点速度

球心速度 `v=(vx,vy)`，角速度 `ω=(ωx,ωy,ωz)`，接触点在球底：

```text
u = ( vx - r·ωy ,  vy + r·ωx )
```

`|u|` 即滑移速度。纯滚动时 `u = 0`，对应 `ωx = -vy/r`、`ωy = vx/r`。

### 3.2 滑动分支（`|u| > 0.012 m/s`）

```text
û = u / |u|
a = -μs · g · û
v ← v + a·Δt
ω ← ω + (5/(2r)) · (a_y, -a_x, 0) · Δt
ωz ← ωz · exp(-λs·Δt)
```

推导：摩擦力 `F = m a` 作用在球底 `(0,0,-r)`，力矩 `τ = (0,0,-r) × (m a_x, m a_y, 0) = (r m a_y, -r m a_x, 0)`；`α = τ/I = (5/(2r))(a_y, -a_x, 0)`。

### 3.3 纯滚动分支

```text
s = |v|
s' = max(0, s - μr·g·Δt)
v ← v · (s'/s)                 // s=0 时跳过
ω ← ( -v_y/r , v_x/r , ωz·exp(-λr·Δt) )
```

每步**重新投影**角速度，消除数值漂移；`ωz` 单独衰减。

### 3.4 限幅与积分

```text
|v| ≤ 12 m/s
|ω| ≤ 900 rad/s
p ← p + v·Δt
q ← normalize( q + 0.5·Δt·(0,ω)·q )
```

四元数每步归一化；`BallState` 的 `q` 存档后仍为单位四元数。

### 3.5 击球模型

`PhysicsWorld.strikeCue(Strike(direction, speed, sideSpin, verticalSpin))`：

```text
n = direction.normalized()
scale = 5·speed / (2r)
ω = ( n.x·vertical·scale , n.y·vertical·scale , -side·scale )
v = n · speed
```

- `side ∈ [-0.5, 0.5]`，`vertical ∈ [-0.5, 0.5]`。
- 高杆/低杆通过 `vertical` 改变 `ωx/ωy`，产生跟进/缩杆；侧旋通过 `ωz` 影响库边和球-球切向。
- 没有球杆抬高角、没有偏杆（squirt）、没有跳球。

## 4. 碰撞

### 4.1 球-球

对每对活动球，`n = (p_b - p_a)/d`，`d < 2r` 时：

```text
位置修正：p_a -= n·overlap/2 ,  p_b += n·overlap/2
接触点：  r_a = n·r ,  r_b = -n·r
接触速度：v_rel = (v_a + ω_a × r_a) - (v_b + ω_b × r_b)
法向速度：v_n = v_rel · n            （>0 表示接近）
法向冲量：j_n = (1 + e_b)·v_n / (1/m_a + 1/m_b)
切向速度：v_t = v_rel - n·v_n
等效质量：m_eff = 1 / (1/m_a + 1/m_b + 2r²/I)
切向冲量：j_t = min( μ_b·j_n , |v_t|·m_eff )
总冲量：  J = -j_n·n - (v_t/|v_t|)·j_t
```

应用：

```text
v_a += J/m_a ;  v_b -= J/m_b
ω_a += (r_a × J)/I ;  ω_b += (r_b × (-J))/I
```

- 两遍求解（`repeat(2)`），减少多球堆叠时的残余重叠。
- 位置修正各 50%，不做偏置（bias）；堆叠场景可能出现轻微可见重叠，但不会爆炸。
- `v_n > 0.03 m/s` 才发 `BallHit`，避免睡眠边缘抖动刷事件。

### 4.2 球-库

库边是四条轴对齐线段；袋口处留缺口。

```text
limitX = 1.27 - r ; limitY = 0.635 - r
若 p.y > limitY 且不在袋口缺口：
  p.y = limitY
  vn = v.y（>0 才处理）
  Jn = m·(1 + e_c)·vn        // 方向 -y
  切向表面速度 s = (vx - ωz·c_y, vy + ωz·c_x)
  Jt = min( μ_c·Jn , |s_t|·m/2 )，方向 -ŝ_t
  v += (Jn + Jt)/m
  ω += (c × (Jn + Jt))/I
  ωz *= 0.82
```

- `c` 是球心到库边接触点的水平向量（例如上库 `(0, r)`）。
- 切向摩擦只考虑 `ωz`（库边接触点竖直自转产生的切向速度），不引入额外的滚动摩擦。
- 穿透超过 2 cm 的异常情况额外把切向速度乘 0.92，作为数值兜底。
- 四个库 + 袋口缺口逻辑在 `collideCushions` / `isCushionGapX/Y`。

### 4.3 袋角

12 个静态圆角柱（角袋两侧 + 中袋两侧），半径 0.012 m：

```text
d = |p - jaw|
若 d < r + 0.012：
  p = jaw + (p-jaw)/d · (r+0.012)
  vn = -(v · n)（>0 才处理）
  J = n·(1+0.62)·vn·m
  v += J/m
  ω += ((n·r) × J)/I
```

- 袋角只做“圆角柱”近似，不是真实袋口几何；用于让球在袋口弹一下再落，而不是直接穿过去。
- 事件复用 `CushionHit`，便于音效/触觉统一。

### 4.4 落袋

- 6 个袋口，捕获半径：中袋 0.075 m、角袋 0.090 m。
- 每步用**扫掠线段** `previousPosition → position` 与捕获圆求交（`segmentCircleHit`），而不是只检查终点。
- 命中后 `active=false`、`asleep=true`、记录 `pocketIndex`，发 `Pocketed`。
- 安全网：若球心离开台面 0.06 m 以外仍未捕获，强制按最近袋口处理，避免飞球。

### 4.5 睡眠

```text
若 |v| < 0.006 且 |ω| < 0.35 持续 0.32 s：
  asleep = true；清零速度/角速度
任何碰撞/击球调用 wake()
```

- 睡眠只影响积分与碰撞遍历，不影响存档。
- 全局 `isMoving()` 用于 UI 判断“球是否全停”；`Settled` 事件每次全部停下发一次。

## 5. 球架与开球

- 15 颗目标球按三角形排列，顶点在 `x = HALF_LENGTH/2`，行距 `2r·cos(30°)`。
- 顺序固定：`1, 9,2, 10,8,3, 11,4,12,5, 13,6,15,14,7`；8 号在第三排中央。
- 白球在 `(-HALF_LENGTH/2, 0)`。
- 无随机扰动，因此同一 `Strike` 在同一初始状态下**完全可复现**。

### 6.1 性能解读

- 480 Hz × 8 步/帧 = 每帧 8 步；按 10 µs/步约 80 µs，占 60 fps 预算（16.6 ms）的 0.5%。
- 桌面 JVM 的绝对数字不能直接外推手机；真机需测 p95 帧时间与发热。
- 最大开销是 16 球两两碰撞（120 对 × 2 遍），但绝大多数球在睡眠时被跳过。

## 7. 已知简化与影响

| 简化 | 影响 | 是否阻塞 |
|---|---|---|
| 无球体形变/接触时间 | 无法模拟真实“粘球” | 否 |
| 无跳球/扎杆 | 花式球路不可用 | 否（产品范围） |
| 无偏杆 squirt | 大侧旋时母球初始方向不会偏移 | 否（可用参数补偿） |
| 无球-台呢各向异性 | 顺/逆草纹差异不存在 | 否 |
| 袋口为圆 + 圆角柱 | 袋口反弹不如真实球台细腻 | 否 |
| 球-球摩擦只作用于接触点 | 没有“投掷”效应的精细建模 | 否 |
| 位置修正无 bias | 多球堆叠可能短暂重叠 | 否（视觉可接受） |
| 固定 480 Hz | 极高速/极端场景仍可能穿透 | 已用 12 m/s 压力测试覆盖正常范围 |

### 8.1 已有自动化

| 测试 | 覆盖 |

### 8.2 建议补充

1. **不变量模糊测试**：随机 10k 次击球，断言位置有限、在台面+0.1 m 内、四元数模长 ±1e-6、无 >1 mm 的球-球重叠、无 >2 mm 的库边穿透。
2. **确定性哈希**：固定 100 个开球种子，记录 3000 步后的状态哈希；跨 JVM/真机比对。
3. **能量单调性**：无击球时总动能不增加（允许碰撞瞬间的数值误差）。
4. **性能基线**：真机 60 s 连续开球，记录每帧物理耗时分位。
5. **袋口回归**：沿袋口边缘 0.5 mm 步进射入，统计“该进/该弹”是否符合预期。

### 8.3 调参优先级

| 症状 | 优先调 |
|---|---|
| 球“太黏”/很快停 | `ROLLING_FRICTION`（0.020） |
| 开球太散/太闷 | `BALL_RESTITUTION`（0.95）、`CUSHION_RESTITUTION`（0.74） |
| 高杆/低杆效果太强 | 击球 `spinScale` 的 `5/(2r)` 系数或 `vertical` 上限 |
| 侧旋库边效果不对 | `CUSHION_FRICTION`（0.18）、`ωz *= 0.82` |
| 袋口“弹不进” | `JAW_RADIUS`、`JAW_RESTITUTION`、袋口捕获半径 |
| 球停不下来 | `STOP_SPEED`、`STOP_TIME` |

所有参数集中在 `TableSpec`，改参数不需要动积分/碰撞代码。

## 9. 选型结论

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **自研（当前）** | 台球专用；袋口/袋角/旋转可精确控制；纯 Kotlin 可单测；无 NDK；APK 小；480 Hz 性能足够 | 需要自己维护数值稳定性；无通用 3D | **采用** |
| Box2D | 成熟 2D 刚体 | 无台球滚动阻力/竖直自转模型；袋口需大量补丁；NDK/JNI 或 Java 移植 | 不采用 |
| Bullet | 功能全 | 过重；3D 球体与台面接触调参复杂；NDK 增加包体/构建 | 不采用 |
| PhysX | 工业级 | 授权/包体/NDK；移动端收益低 | 不采用 |

**结论：自研物理通过最小原型验证，可执行，允许进入阶段 1；前提是按第 8.2 节补齐不变量/真机性能测试。**
