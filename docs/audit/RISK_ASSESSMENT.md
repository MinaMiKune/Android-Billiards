# 风险评估（阶段 0）

- 方法：可能性（1–5）× 影响（1–5）= 风险分；≥15 为高，8–14 为中，≤7 为低。
- 范围：技术、交付、兼容性、产品/合规；不含纯商业风险。
- 结论：**没有“必须推翻架构”的风险**；有 3 项高风险（真机性能数据、发布签名、无障碍），必须在阶段 1 关闭。折叠屏专项已由产品决定搁置，降为已接受风险。

## 2. 高优先级风险

### R1 — 真机已运行，但缺少帧率/发热数据

| 项 | 内容 |
|---|---|
| 可能性 | 4（高） |
| 影响 | 4（严重：可能无法稳定 60 fps） |
| 评分 | **16（高）** |
| 证据 | 用户真机运行正常，但未提供机型/系统版本/gfxinfo；本机无 adb、无 `/dev/kvm`、无 emulator；CI 仅 API35 ATD + SwiftShader；代码无 FPS 计数器 |

| 关闭标准 | 目标机 60 s 对局 p95 ≤16.6 ms，无持续降频；低画质档在低端机 ≥30 fps |

### R9 — Release 产物未签名

> **状态：已关闭（2026-11-17，阶段 8）。** 已建立 RSA 4096 PKCS12 keystore
> （别名 `breakpoint`，有效期 30 年）；`release` buildType 在提供
> `RELEASE_*` 环境变量/gradle 属性时自动签名，产出签名 APK
> （APK Signature Scheme v2，`apksigner verify` 通过、证书指纹与 keystore
> 一致）与签名 AAB（`jarsigner -verify` 通过）；GitHub Actions 在配置
> secrets 后自动构建，推 `v*` tag 自动发布签名产物 + SHA-256 校验和 +
> R8 映射表。流程与指纹见 `docs/release/SIGNING.md`。release 产物的
> “可安装/可升级”验证受本机无模拟器限制，留待真机/远端 CI 复验。

| 项 | 内容 |
|---|---|
| 可能性 | 4（高） |
| 影响 | 4（严重：无法上架/分发正式版） |
| 评分 | **16（高）** |
| 证据 | `assembleRelease` 生成的是 unsigned APK（408,810 B）；无 signingConfig；CI release job 上传 debug APK 到 GitHub Release |
| 缓解 | 阶段 1 建立 keystore（本地/CI secret）、配置 `signingConfigs`、产出 AAB；密钥备份与权限流程 |
| 关闭标准 | 签名 AAB 可安装、可升级、`apksigner verify` 通过 |
| 责任 | 发布/本人 |

### 阶段 1 第 1 周（门禁）

1. **R1**：记录真机型号/系统版本；跑 60 fps / 发热 / 低画质档。

5. **R2**：记录“折叠屏专项搁置”的产品决策，不投入开发。

6. **R8**：API 37 CI（镜像可用时）+ GL 错误/帧计数断言。

## 4. 未关闭的产品/架构问题

这些不是“架构缺陷”，但需要产品拍板；在拍板前不应宣称阶段 0 完全结束：

| 编号 | 问题 | 默认建议 |
|---|---|---|
| Q1 | 手机是否允许反向竖屏？ | 保留 `fullSensor`；若不需要，改 `sensorPortrait`（大屏仍自适应） |
| Q2 | 折叠屏是否需要铰链避让/双栏？ | **已决定搁置**；保留基础自适应，不引入 WindowManager |
| Q3 | 是否需要无障碍为发布门槛？ | 建议是；至少主流程 TalkBack 可用 |
| Q4 | 发布签名由谁持有/如何备份？ | 立即建立，避免后期换签名 |
| Q5 | 是否接受“进程死亡回到最近稳定局面”？ | 接受；写入 FAQ |
| Q6 | 是否需要英文/多语言首发？ | 至少英文，否则海外不可用 |

## 5. 结论

| 项 | 结论 |
|---|---|
| 是否存在阻塞性架构风险 | **否** |
| 高风险数量 | 3（R1 性能、R9 签名、R10 无障碍）；R9 已关闭（阶段 8，2026-11-17） |
| 中风险数量 | 5（R6/R8/R11/R13/R15） |
| 可否进入阶段 1 | **可以，条件式**：先执行第 3 节第 1 周门禁；R1/R9 未关闭前不得发布 |
| 残余风险 | 真机性能数据、折叠屏未优化（已接受）、触觉多机型差异、无遥测；均可用测试/降级/产品决策管理 |
